# 簡易待辦清單（指令 + 檔案）

用 Node 內建能力：從命令列接收指令，對待辦做讀、寫、改、刪。資料存在另一個檔案（txt、json 都行）。不裝套件、不用 HTTP。

## 資料

每筆至少有：

- `id`：唯一識別
- `title`：標題（非空字串）

`done` 可有可無。儲存格式自己定。

## 指令（CRUD）

由 `process.argv` 判斷要做哪件事。名稱自己定，行為要齊：

| 動作 | 預期 |
|------|------|
| 寫（新增） | 把一筆寫進檔案 |
| 讀 | 列出全部，或用 `id` 讀一筆；不存在要失敗 |
| 改 | 用 `id` 改標題（或完成狀態）；不存在要失敗 |
| 刪 | 用 `id` 刪掉；不存在要失敗 |

程式結束後再開一次，資料還在。

## 不做（這次）

HTTP、伺服器、登入、畫面、資料庫、額外套件。

## 檢測

給檢測者照表跑，不要改 `todoList.ts`。不寫死 `node:test`：指令名稱與欄位名以程式為準（目前動作是 `add` / `read` / `update` / `delete`，標題欄是 `value`，旗標是 `-v` / `--value`、`-i` / `--id`）。

每組都做兩段：

1. **指令本身**：在 `Tasks/CRUD` 執行。成功的案例行程結束碼是 0，且標準輸出有這次結果（不是只有拋例外）。該失敗的案例結束碼不是 0，檔案內容與執行前相同。
2. **對資料判讀**：讀完標準輸出／標準錯誤後，打開 `data.json`，對照該組的「資料」欄。輸出說成功但檔案沒變，算失敗。

開始前把 `data.json` 備份，寫成 `[]` 當起點。全部跑完還原備份。下面指令依序執行，後一組沿用前一組留下的檔案。

| 組 | 指令 | 資料 |
|----|------|------|
| 新增 | `node todoList.ts add -v "買牛奶"` | 陣列多一筆，標題是「買牛奶」，`id` 非空 |
| 新增第二筆 | `node todoList.ts add -v "寫作業"` | 兩筆都在，`id` 彼此不同 |
| 新增空標題 | `node todoList.ts add -v ""` | 失敗；仍是上面兩筆 |
| 讀全部 | `node todoList.ts read` | 輸出能對上檔案裡的兩筆（筆數與標題） |
| 讀一筆 | `node todoList.ts read -i <第一筆 id>` | 輸出只有該筆；檔案仍是兩筆 |
| 讀不存在 | `node todoList.ts read -i "不存在"` | 失敗；檔案仍是兩筆 |
| 改標題 | `node todoList.ts update -i <第一筆 id> -v "買麵包"` | 該筆標題變「買麵包」，`id` 不變；另一筆不變 |
| 改不存在 | `node todoList.ts update -i "不存在" -v "沒這筆"` | 失敗；檔案與上一列相同 |
| 刪一筆 | `node todoList.ts delete -i <第一筆 id>` | 該筆消失；「寫作業」還在 |
| 刪不存在 | `node todoList.ts delete -i "不存在"` | 失敗；檔案與上一列相同 |
| 持久 | 再開一次 `node todoList.ts read` | 與刪完之後的檔案相同，不是只活在上一個行程的記憶體 |
