# 提示（給輔助者，一次只升一階）

## 1 觀念

這題在練：命令列進腳本時已經是陣列，不是你要再切的字串。前兩格是 Node 自己填的（執行檔、腳本路徑），後面才是使用者打的。要把指令裡的數值取出來，Node 有現成的 `parseArgs`，說明自己去查，不必手寫規則。檔案末尾的入口只在「被 `node` 直接跑」時印結果。兩題測試都是真的 `node answer.ts …`，不是把整理過的參數塞進函式。

## 2 方向

官方文件關鍵字：`process.argv`、`util.parseArgs`。直接當 CLI 跑時，讀的就是這次行程的命令列。不要 yargs、不要 `startsWith('--')`。自測與評分都是 `node playground/cli-args/answer.ts …`。

## 3 縮小

對一下失敗的案例在測哪一種：是不是回傳了含 node／腳本的整段 argv、布林與字串型別設反、位置參數被拒。若 `node --test` 印出一堆 CLI 輸出，先看是不是在模組頂層（沒判斷主模組）就呼叫了公開函式。兩個函式通常是接官方 API，不要自己寫 parser。
